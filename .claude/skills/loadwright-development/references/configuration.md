# Configuration — Design Reference

> **Status: specification for software that does not exist yet.** Nothing
> described in this document has been built. Every statement here defines
> *intended* behavior, not current behavior — read it as a build order, not
> as documentation of a working system. When implementation diverges from
> this document, update the document in the same commit.


Loadwright is configured entirely through one generated initializer,
`config/initializers/loadwright.rb`, produced by a Rails generator
(`rails generate loadwright:install`). Every behavior a reasonable person
might want to toggle should be a key here — the goal is that someone should
almost never need to read gem source to know what's adjustable.

Defaults are chosen to be the **safest, narrowest, most conservative**
option in every case. Widening scope (more environments, more concurrency,
mutating requests, production access) is always an explicit opt-in.

## Four things about this file that are not stylistic

1. **The `if defined?(Loadwright)` guard is mandatory.** Rails evaluates
   every initializer in every environment, but this gem lives in the
   `:development, :test` Gemfile group. Without the guard, booting
   production raises `NameError` and the app doesn't start. Bullet solves
   it the same way. There must be a spec asserting the generated file
   contains this guard.
2. **Values referencing `Faker`, `Loadwright::TestUsers`, etc. are
   illustrative placeholders** demonstrating the expected shape, not real
   APIs the gem provides. The generator should emit them commented out or
   clearly marked so nobody assumes they work as-is.
3. **Every key carries provenance.** `Loadwright::Configuration` records,
   per key, whether the resolved value came from the built-in `:default`, a
   `:preset`, or an `:explicit` assignment. This is not bookkeeping for its
   own sake — two things depend on it:

   - `reporting.md` requires a resolved-config snapshot answering "was this
     run safe, and is this data trustworthy." `lock_timeout_ms: 1000` is
     far less useful than `1000 (from the :conservative preset)`.
   - `run-comparison.md`'s comparability gate compares config fingerprints.
     **The fingerprint is computed over resolved values, never assigned
     ones.** Two runs with identical explicit config but different presets
     are not comparable; a fingerprint over assignments would call them
     comparable and produce a plausible, meaningless delta. That is the
     gate failing silently, which is worse than it refusing loudly.

   Provenance is also what makes the preset/override rule below
   implementable at all: plain `attr_accessor`s cannot distinguish
   `config.lock_timeout_ms = 3000` from the identical default.

4. **Defaults that reference Rails are resolved lazily**, at run start
   rather than when the attribute is defined. `Rails.root`, the application
   module name, and anything derived from them do not exist when the gem's
   own suite loads `Loadwright::Configuration`. Eager evaluation would
   either raise on load or freeze a wrong value that a later Rails boot
   never corrects.

## Full template

```ruby
# config/initializers/loadwright.rb
#
# Generated by `rails generate loadwright:install`.
#
# The `if defined?` guard below is REQUIRED — see the note in
# references/configuration.md. Removing it will break production boots.

if defined?(Loadwright)
  Loadwright.configure do |config|
    # =====================================================================
    # EXECUTION MODE — see references/execution-modes.md
    # :in_process finds query-structure problems fast with zero setup.
    # :http finds capacity problems with real server concurrency.
    # =====================================================================

    config.execution_mode = :in_process

    # :in_process cannot honestly measure concurrency, so it forces
    # concurrency_levels to [1] and marks concurrency-dependent findings
    # "unavailable" rather than reporting fabricated numbers. Enabling
    # this allows in-process threading with those caveats still applying.
    config.allow_in_process_threading = false

    # :http mode only. Loadwright boots a server unless a URL is given.
    config.http_server_command = nil # nil = auto (Puma)
    config.http_boot_timeout = 30    # seconds to wait for health

    # Targeting an already-running app instead of booting one. A
    # non-loopback target bypasses the local environment gate entirely —
    # the thing receiving load is a different process, possibly a
    # different machine. Gated separately from allow_production; see
    # references/production-safety.md Layer 1b.
    config.http_target_url = nil
    config.allow_remote_http_target = false

    # =====================================================================
    # SAFETY — read this section first. Defaults here are intentionally
    # restrictive. Widening them is a deliberate decision, not a default.
    # =====================================================================

    # Only these environments may run Loadwright at all. Anything else
    # aborts before any config below is even evaluated.
    config.enabled_environments = [:development, :test]

    # Extra hostname/DATABASE_URL heuristics checked even inside an allowed
    # environment. See references/production-safety.md for the full flow.
    config.production_hostname_patterns = [
      /\.rds\.amazonaws\.com\z/,
      /^prod-/,
      /\.internal\z/,
    ]

    # Must be true, AND the confirmation phrase must be typed, AND
    # --i-understand-the-risk must be passed, for a run to proceed outside
    # enabled_environments. Leave false absent a reviewed reason.
    config.allow_production = false

    # What the user must type to confirm a production-adjacent run. Defaults
    # to the application's module name, so the phrase is specific to this app
    # and cannot be guessed generically.
    #
    # There is deliberately NO generic fallback. A hardcoded string would
    # defeat the reason the default is app-specific. If it cannot be resolved
    # and a run takes the production-adjacent path, Loadwright refuses and
    # asks for an explicit value; on an ordinary dev/test run it is never
    # consulted. See production-safety.md Layer 3.
    #
    # (Rails >= 7.0 is the floor, so module_parent_name is always defined and
    # the old respond_to? hedge is gone.)
    # config.confirmation_phrase = "MyApp"

    # GET/HEAD/OPTIONS only by default. Set true to allow discovered
    # POST/PUT/PATCH/DELETE endpoints to be exercised under load.
    config.allow_mutating_requests = false

    # Abort the remaining run if observed error rate crosses this fraction.
    #
    # Contention errors (lock waits, pool timeouts, statement timeouts) are
    # EXCLUDED from this figure — they belong to the resource guard, which
    # retreats per-endpoint rather than killing the run. This threshold is for
    # "this endpoint is broken": wrong auth, missing route, 500s. See
    # resource-contention.md Part 6.
    config.max_error_rate_before_abort = 0.20

    # Endpoints x scale factors x concurrency levels x requests per cell can
    # reach hours. Loadwright prints the estimated duration and worst-case
    # backoff budget before starting, and prompts for confirmation above this
    # many minutes. Required by CLAUDE.md section 2 corollary 7.
    config.long_run_confirmation_threshold_minutes = 10

    # =====================================================================
    # SIDE-EFFECT CONTAINMENT — endpoints under load can do things well
    # beyond the database. All default to ON; turning any off means real
    # emails/jobs/webhooks may fire from a load test.
    # =====================================================================

    # Forces ActionMailer delivery_method to :test for the run.
    config.suppress_mail_delivery = true

    # Forces ActiveJob queue_adapter to :test for the run, so jobs are
    # recorded (and counted in the report) rather than performed.
    config.suppress_background_jobs = true

    # Blocks outbound HTTP to anything not in outbound_http_allowlist.
    # Requires webmock; if unavailable, Loadwright warns loudly rather
    # than silently running without containment.
    config.block_outbound_http = true
    config.outbound_http_allowlist = ["localhost", "127.0.0.1"]

    # If containment can't be enforced (missing dependency, custom mailer,
    # etc.), abort rather than proceed unprotected.
    config.abort_if_containment_unavailable = true

    # =====================================================================
    # RESPONSE ANALYSIS — the response is what proves the endpoint
    # actually did the work. See references/response-analysis.md.
    # =====================================================================

    # An endpoint whose response fails these checks is reported as
    # `inconclusive`, never as healthy. A 403 in 4ms with 1 query is not a
    # fast endpoint — it's an endpoint that did nothing.
    config.require_successful_response = true
    config.require_schema_valid_response = true

    # Warn when data was seeded but the endpoint returns an empty
    # collection — usually means factories don't match the endpoint's
    # scope (tenant, published flag, soft-delete, ownership).
    config.warn_on_empty_response_with_seeded_data = true

    # Query-count slope is measured against RETURNED record count, not
    # seeded count — a paginated endpoint hides its N+1 from seed-based
    # slope entirely. These params are swept to vary result size.
    config.page_size_parameters = %w[per_page limit page[size] pageSize]
    config.page_size_sweep = [5, 25, 100]

    # Over-fetch hints: tables/columns queried but absent from the
    # response. Reported as hints only — data is legitimately loaded for
    # authorization and filtering without being serialized.
    config.detect_overfetching = true

    # Unbounded-collection detection via payload growth.
    config.max_response_bytes_warning = 1_048_576 # 1 MB
    config.payload_growth_correlation_threshold = 0.8

    # Attribute N+1s to the serializer/template layer where possible —
    # serializer-level N+1s are the most commonly missed kind in API apps.
    config.serializer_attribution = true

    # =====================================================================
    # RESOURCE CONTENTION & BACKOFF — see references/resource-contention.md
    # Loadwright retreats from contention; it never kills sessions.
    # That doc's tuning table explains what each knob below trades away.
    # =====================================================================

    # :conservative (shared dev DB), :balanced (default, local DB you own),
    # :aggressive (throwaway/containerized DB). A preset fills in only the
    # keys you have not set yourself — anything you assign explicitly wins,
    # regardless of the order you assign it in, and regardless of whether the
    # value you assigned happens to equal the default. See the provenance note
    # near the top of this file for why that requires more than attr_accessor.
    config.contention_profile = :balanced

    # Fail-fast timeouts applied to Loadwright's own connections so a
    # blocked query errors in seconds instead of hanging the run.
    config.lock_timeout_ms = 3_000
    config.statement_timeout_ms = 10_000

    # Baseline health check before the run. Aborts if the database is
    # already contended (migration running, long transaction, etc.).
    config.abort_on_unhealthy_baseline = true

    # Out-of-pool health sampling cadence.
    config.health_poll_interval_ms = 500

    # Tier 3 statistical degradation detection: p95 exceeding this
    # multiple of the endpoint's concurrency-1 baseline, for this many
    # consecutive windows, counts as contention.
    config.latency_degradation_multiplier = 4.0
    config.degradation_windows_before_backoff = 3

    # The backoff ladder (rungs 1-2).
    config.backoff_initial_delay_ms = 250
    config.backoff_multiplier = 2.0
    config.backoff_max_delay_ms = 15_000
    config.backoff_jitter = 0.3 # fraction; prevents synchronized retries
    config.max_backoff_attempts = 4

    # Ladder rungs 3-5: quarantine, cooldown, global abort.
    config.post_quarantine_cooldown_ms = 5_000
    config.max_consecutive_quarantines = 3
    config.max_health_check_retries = 3

    # =====================================================================
    # DISCOVERY — where Loadwright learns what endpoints exist
    # =====================================================================

    config.openapi_spec_paths = [
      Rails.root.join("swagger/v1/swagger.yaml"),
    ]

    # Scanned in "recording" mode to capture real requests from your own
    # specs. See discovery-and-load-engine.md for why this records rather
    # than statically parses.
    config.integration_spec_paths = [
      Rails.root.join("spec/requests"),
      Rails.root.join("spec/integration"),
    ]

    # Fall back to Rails route introspection for anything neither source
    # covers (lower fidelity — no example params).
    config.route_discovery = true

    config.excluded_paths = [
      %r{^/rails/},
      %r{^/admin/},
      %r{^/health},
    ]

    # If set, ONLY these paths are considered. nil = no extra restriction.
    config.included_paths = nil

    # Real IDs for path params like /posts/{id}. Resolved from seeded
    # records first; this is the override for anything that can't be
    # inferred (slugs, UUIDs, composite keys). Without resolution most
    # nested endpoints 404 and the run reports nothing useful.
    config.path_param_overrides = {
      # "/api/v1/posts/{slug}" => { slug: -> { Post.first&.slug } },
    }

    # =====================================================================
    # AUTH
    # =====================================================================

    # :none, :bearer_token, :session, or :custom
    config.auth_strategy = :bearer_token

    # Illustrative — replace with your app's own token logic. May return a
    # single token or a collection; a collection rotates identities across
    # requests, which matters for multi-tenant apps where single-identity
    # traffic can make a badly-scoped query look fine.
    config.auth_token_provider = -> { ENV.fetch("LOADWRIGHT_TOKEN", nil) }

    # Seed and rotate across this many identities when the provider
    # doesn't supply its own collection.
    config.test_identity_pool_size = 5

    config.default_headers = { "Accept" => "application/json" }

    # =====================================================================
    # DATA SEEDING — FactoryBot-driven population at scale
    # =====================================================================

    config.factory_bot_enabled = true

    # Resource name => factory (+ optional trait). Anything unlisted is
    # skipped for seeding; its endpoints can still be hit.
    config.factory_map = {
      # "user" => { factory: :user },
      # "post" => { factory: :post, trait: :with_comments },
    }

    # Population sizes tested, in order. Query-count-vs-scale-factor is the
    # core N+1 heuristic — see discovery-and-load-engine.md.
    config.scale_factors = [1, 10, 50, 200]

    # Seed in batches with a health check between them, so a large scale
    # factor can't lock the table in one giant transaction.
    config.seed_batch_size = 50

    # :delete_created_rows (default) — tracks IDs Loadwright inserted and
    #   removes only those. NEVER truncates whole tables.
    # :transactional_rollback — wraps the run in a transaction; fastest,
    #   but connection-pool behavior won't match a real multi-connection
    #   scenario, so pool findings are less trustworthy.
    # :leave — do nothing; useful for inspecting seeded state afterward.
    config.seed_cleanup_strategy = :delete_created_rows

    # Escape hatch for resources with no factory at all. Not the primary
    # uniqueness mechanism — that's your factories' own sequences.
    config.unique_field_generator = nil

    # =====================================================================
    # LOAD SHAPE
    # =====================================================================

    config.concurrency_levels = [1, 5, 20]
    config.requests_per_endpoint_per_level = 25
    config.request_timeout = 5 # seconds
    config.warmup_requests = 3 # discarded from stats

    # =====================================================================
    # INSTRUMENTATION
    # =====================================================================

    config.detect_n_plus_one = true
    config.track_memory_allocations = true
    config.track_connection_pool = true

    # ActiveRecord's query cache dedupes identical queries within a
    # request, which can hide a textbook N+1 completely. Disabled during
    # runs so query counts reflect code structure. When left enabled,
    # N+1 findings are labelled as potentially undercounted.
    config.disable_query_cache_during_run = true

    # Where the time actually went: db / view / GC / external / other.
    # An endpoint that is 80% serialization is not a database problem.
    config.track_time_breakdown = true
    config.track_gc_stats = true

    # EXPLAIN runs after the load phase, never during it. ANALYZE is used
    # only on SELECTs — EXPLAIN ANALYZE executes the statement, so running
    # it on a write would perform the write.
    config.run_explain_on_slow_queries = true
    config.explain_top_n_queries = 5
    config.seq_scan_row_threshold = 10_000

    # Cold-cache performance is what users hit right after a deploy.
    # Measured and reported alongside warm rather than discarded.
    config.measure_cold_cache = true

    # Postgres only; requires pg_stat_statements. Ignored elsewhere.
    config.track_pg_stat_statements = true

    config.slow_query_threshold_ms = 100

    # Percentiles the sample size can't support are omitted, not caveated.
    # Raising requests_per_endpoint_per_level is the documented fix.
    config.min_samples_for_percentiles = { p50: 20, p95: 100, p99: 500 }

    # Flag Puma threads x workers exceeding the AR pool size even when no
    # contention was observed — it's a latent problem worth stating.
    config.check_pool_vs_server_threads = true

    # =====================================================================
    # RUN HISTORY & COMPARISON — see references/run-comparison.md
    # =====================================================================

    config.run_history_dir = Rails.root.join("tmp/loadwright/runs")
    config.run_history_limit = 50

    # Latency on a laptop routinely moves 10-20% between identical runs.
    # Query-count deltas are near-deterministic and are the primary
    # regression signal; latency deltas must clear this threshold AND the
    # measured noise floor before being called a regression.
    config.regression_threshold_pct = 20
    config.fail_on_regression = false

    # =====================================================================
    # REDACTION — reports contain request/response bodies and SQL from a
    # real database. Sanitizing happens at collection time, not render
    # time, so secrets never reach the persisted run record either.
    # =====================================================================

    # Rails already knows what's sensitive; honor its declaration.
    config.honor_rails_filter_parameters = true
    config.redact_header_patterns = [/authorization/i, /cookie/i, /api[-_]?key/i]
    config.redact_sql_bind_values = true
    config.include_response_bodies = false
    config.redact_additional_patterns = []

    # =====================================================================
    # THRESHOLDS — optional pass/fail for scripted use
    # =====================================================================

    config.fail_on_n_plus_one = false
    config.p95_latency_budget_ms = { default: 500 }

    # =====================================================================
    # REPORTING
    # =====================================================================

    config.report_formats = [:html, :markdown]
    config.report_output_dir = Rails.root.join("tmp/loadwright")
    config.report_filename_pattern = "%Y%m%d-%H%M%S-report"

    # Always write a report even when the run aborts partway.
    config.write_partial_report_on_abort = true

    # =====================================================================
    # NOTIFICATIONS (optional)
    # =====================================================================

    config.slack_webhook_url = nil
  end
end
```

## Adding a new config key — checklist

1. Add it to the template above, in the right section, with an inline
   comment explaining what it does and why the default is what it is.
2. Add a matching attribute to `Loadwright::Configuration` with the same
   default, via the `setting` DSL so it participates in provenance
   tracking. If the default references Rails, pass it as `lazy:`.
3. Add a spec asserting the default value *and* that changing it changes
   behavior — not just that the attribute exists.
3b. If the key affects **what was measured** rather than how it is
   presented, add it to `Configuration::COMPARABILITY_KEYS` so two runs
   differing on it are correctly refused as incomparable.
4. If it affects safety, containment, or contention handling, it belongs
   in one of the three sections above the fold, not buried later.
   Visibility matters as much as functionality here.
5. Document it in the README's configuration walkthrough. There is a spec
   asserting the README, the generated initializer, and
   `Loadwright::Configuration` expose the same key set — see
   `references/readme-and-examples.md`. Adding a key in only one or two of
   the three will fail that spec, deliberately.
