# OpenAPI-driven

Discovery *and* response validation from a schema you already maintain.

## Who this is for

You have an OpenAPI/Swagger document — most likely generated by
[rswag](https://github.com/rswag/rswag) from your request specs. This is the
richest discovery source Loadwright has: it knows the path, the verb, the
parameters, and the response schema.

## What the schema buys you

Everything else in Loadwright can tell you an endpoint returned 200 in 4ms
with one query. Only the schema can tell you the body was wrong.

An endpoint that returns 200 with a payload no longer matching its contract
has broken, and a query-counting tool calls it the healthiest endpoint in the
API. With `require_schema_valid_response` on, that endpoint is
**inconclusive** — the validation error is reported, and no performance
verdict is attached to a response that did not prove it did the work.

## What it trades away

**Your document has to be accurate.** Loadwright fails loudly on a partial
parse rather than testing the half it understood. That is deliberate: a
half-parsed document reports the endpoints it missed as *absent* rather than
as *skipped*, and an API that is half-tested reads exactly like an API that
is clean.

If the parse fails you get an error naming the document and the construct it
choked on, not a run.

**Parser version note.** The underlying parser is a 3.0 parser. It accepts a
`3.1.0` version string but rejects `webhooks`, type arrays, and numeric
`exclusiveMaximum`. If your document uses 3.1-only constructs, you will find
out at parse time rather than silently.

## Path parameters

Resolution order, most trustworthy first:

1. **Seeded records** — ids Loadwright created this run
2. **Recorded ids** — from integration-spec recording, if enabled
3. **`path_param_overrides`** — yours, for anything the above cannot reach
4. **The document's `example`** — last resort

The document's examples are last on purpose. An example id of `1` 404s
against a freshly seeded database, and a 404 measured at 3ms is the classic
false clean.

## Running it

```
bundle exec loadwright run --dry-run
bundle exec loadwright run --execute
```

The dry run prints which source each endpoint came from and how many were
skipped for want of a usable example.
